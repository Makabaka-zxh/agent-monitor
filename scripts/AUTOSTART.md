# Windows 登录后自动启动

在拥有 Codex / Claude Code 会话记录的当前 Windows 用户下，从项目目录执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\register-autostart.ps1 `
  -PublicUrl "https://your-node.your-tailnet.ts.net" `
  -PythonPath "D:\MonitorRuntime\Scripts\python.exe" `
  -StateDir "D:\MonitorData\hub" `
  -Port 8766
```

替换为实际 HTTPS 来源、已有 Python 环境和原数据库目录。后面三个参数可省略，默认取项目 `.venv\Scripts\python.exe`、`.state\hub` 和端口 8766；相对路径按项目目录解析。

这会注册固定任务 `\AgentMonitor-PublicHub`，在当前用户登录后调用 `run-public.ps1`，使用 Interactive / Limited 权限和隐藏窗口，不保存密码。除登录触发外，同一任务从注册后一分钟起每分钟获得一次启动机会，重复规则不设到期时间；已有运行实例时由 `IgnoreNew` 跳过，不额外启动服务。保留原有失败重试设置（间隔一分钟、最多 3 次）和无执行时长上限。注册不停止当前服务，不修改 HTTPS 映射。若同名任务并非本项目、当前用户创建，脚本会拒绝覆盖。

周期触发用于补上“动作已启动，但应用进程随后异常退出”的恢复缺口，不能仅凭 `RestartOnFailure` 配置和非零退出码就认定会自动重启。它要求当前用户仍已登录、电脑处于可运行状态；不会唤醒电脑。周期触发本身不会处理仍存活但卡死的实例，使用 `run-public.pyw` 时另有下述事件循环检查。需要主动停机维护时，先禁用该任务再停止服务，否则下一次周期触发可能重新启动。重新启用后会继续周期调度。

周期触发被 `IgnoreNew` 跳过时，任务的上次运行时间和结果仍可能更新；这不等于原实例退出或重新启动。判断恢复与重复启动，应同时核对运行实例、进程身份、实际监听和健康检查。

移除本项目的自启动与恢复任务：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\register-autostart.ps1 -Uninstall
```

卸载同样检查任务归属，只删除本项目任务，不终止运行中的服务、不删除数据库，也不关闭 Funnel。`-ExecutionPolicy Bypass` 仅作用于这次 PowerShell 进程。

## 无窗口启动器的监听恢复

已使用 `run-public.pyw` 的实例会检查自己持有的监听 socket，不能仅凭进程存在或旧的“运行中”标记判断服务可用。Windows 接收连接失败或取消时，底层可能关闭监听 socket，而服务循环仍在继续；启动器现在会检测这种情况，并在同一进程、同一回环地址和端口重新建立监听，复用已有应用和后台任务。

每个进程最多恢复 3 次，单次异步建立监听的等待上限为 5 秒；下一次检查确认实际监听后才恢复“运行中”状态。端口已被占用、恢复失败或次数耗尽时，记录失败并以非零状态退出；进程退出后由任务计划的周期触发补启动，实际恢复仍需核验新实例、监听和健康检查。不会抢占其他进程的端口、重复启动采集任务、修改任务计划或更换状态目录。仍使用 Windows 独占绑定；若已有连接或系统端口状态阻止重新绑定，会如实失败。

状态目录中的 `launcher-events.json` 只保留最近 32 条匿名生命周期事件，包含固定事件类别、UTC 时间、恢复次数及有限的异常类型和数值错误码。经过格式核验的前次事件会跨重启保留，不保存异常消息、调用栈、域名、账号、请求或任务内容。诊断文件无法可靠写入时，启动器终止恢复并进入失败退出流程，同时尽力清除旧的“运行中”标记；如果系统也拒绝删除，该旧标记仍可能残留。

监听恢复依赖事件循环继续运行。为覆盖“进程仍在，但服务循环已停止前进”，无窗口启动器在成功启动后另启一个内存中的监测线程。它每 5 秒检查服务循环的进展；连续 120 秒没有进展后，再观察至少 30 秒，仍未恢复才以固定非零码 70 退出，由任务计划的下一次周期触发恢复。正常异步等待和后台采集不阻塞循环心跳；短暂迟延不会达到退出门槛。

如果监测线程本身超过 15 秒未获调度（例如电脑睡眠或进程挂起），会重新计时完整的观察和确认窗口。启动完成前监测尚未启用；正常关闭先停止监测线程，保留原有应用和工作线程清理流程。这个方案不是主机级监控：整个进程无法运行、原生扩展持续占有 Python 执行锁、监测线程持续无法获调度、系统故障，以及开始关闭后的无限等待仍不在覆盖范围内。达到门槛后的退出是立即终止，会中断尚在执行的请求；不会另启服务或修改任务计划。

`launcher-heartbeat-failure.json` 只保留最近一次停滞观察，正常心跳不写盘；字段为固定事件、时间、阈值和退出码，不包含进程标识、URL、路径、账号或任务内容。记录由独立线程尝试，最多等待 0.5 秒；写盘失败或卡住不能阻止退出。最后一刻恢复进展或正常关闭时，退出会取消，所以该文件只证明观察到停滞，不能单独证明进程已经退出或重启。应以新实例、实际监听和健康检查验证恢复，不能据此推断长期稳定性。
